# Soul of Waifu для Linux

**[English version](README.md)**

Неофициальный порт [Soul of Waifu](https://github.com/jofizcd/Soul-of-Waifu) v2.5.1
(автор — jofizcd) на Linux. Оригинал выходит только под Windows. Этот порт работает на Arch Linux,
Debian, Ubuntu и их производных (EndeavourOS, Manjaro, CachyOS, Linux Mint, Zorin OS, Pop!_OS
и т. д.), и локальная нейросеть
работает сразу после установки: установщик сам ставит llama.cpp и модель, а программа
подключается к ним по OpenAI-совместимому API.

## Установка

Нужны: x86-64, Arch Linux, Debian 12+ / Ubuntu 22.04+ или производная, около 20 ГБ
свободного места и пользователь с `sudo`. Видеокарта NVIDIA не обязательна, но сильно
ускоряет работу.

Программа одна и та же для всех дистрибутивов; отличается только скрипт установки, потому
что системные пакеты ставятся пакетным менеджером конкретного дистрибутива.

**Arch Linux** и производные:

```bash
sudo pacman -S --needed git
git clone https://gitlab.projectmiku.cc/opensrc/soul-of-waifu-linux.git
cd soul-of-waifu-linux
./install_arch.sh
```

**Debian / Ubuntu** и производные:

```bash
sudo apt install -y git
git clone https://gitlab.projectmiku.cc/opensrc/soul-of-waifu-linux.git
cd soul-of-waifu-linux
./install_debian.sh
```

После этого запускайте **Soul of Waifu** из меню приложений или командой `./launch.sh`.

Первая установка скачивает примерно 5-8 ГБ (Python-пакеты, llama.cpp, модели) и занимает
15-40 минут. Всё ставится в склонированную папку; в системные каталоги попадают только
системные пакеты.

> **Если у вас NVIDIA:** сначала поставьте проприетарный драйвер (Ubuntu/Zorin: *Программы
> и обновления → Дополнительные драйверы* или `sudo ubuntu-drivers install`) и
> перезагрузитесь. Установщик выбирает CUDA-сборку по выводу `nvidia-smi`. Без рабочего
> драйвера он ставит вариант для CPU/Vulkan. На Arch поставьте `nvidia-open` (или
> `nvidia-open-dkms`) и `nvidia-utils`, как описано в [Arch Wiki](https://wiki.archlinux.org/title/NVIDIA).

### Параметры установщика

У `install_arch.sh` и `install_debian.sh` одинаковые параметры.

| Параметр | Что делает |
|---|---|
| *(без параметров)* | Определить железо автоматически |
| `--cpu` | Только процессор, CUDA нигде не используется |
| `--torch=cu128\|cu126\|cpu` | Сборка PyTorch (cu128: драйвер ≥ 570, нужна для RTX 50xx; cu126: драйвер ≥ 525) |
| `--llama=cuda\|vulkan\|cpu` | Сборка llama.cpp (CUDA: драйвер NVIDIA ≥ 570 и Ubuntu 24.04+ / glibc ≥ 2.38; Vulkan: любая видеокарта) |
| `--no-model` | Не скачивать модель по умолчанию |
| `--model-url=URL` | Скачать указанный GGUF вместо модели по умолчанию |

Установщик можно запускать повторно: готовые шаги пропускаются, а ваш `llama.conf`
остаётся как был.

### Обновление

```bash
cd soul-of-waifu-linux
git pull
./install_arch.sh     # или ./install_debian.sh
```

## Что делает установщик

1. Ставит системные библиотеки (Qt/OpenGL/звук, ffmpeg, инструменты сборки): на Arch через
   `pacman -Syu` (заодно обновляет систему — частичные обновления на Arch не поддерживаются;
   Vulkan-драйверы для AMD/Intel добавляются автоматически), на Debian/Ubuntu через apt.
2. Ставит [uv](https://docs.astral.sh/uv/) с Python 3.11 и все Python-зависимости в `./.venv`
   (через `install_linux.sh`). Системный Python не трогается.
3. Скачивает официальную сборку [llama.cpp](https://github.com/ggml-org/llama.cpp) в `./llama`:
   - **CUDA**, если драйвер NVIDIA версии 570 или новее и система — Arch или
     Ubuntu 24.04+ / Zorin 18+ (официальной CUDA-сборке нужна glibc 2.38);
   - иначе **Vulkan**: AMD, Intel, старые драйверы NVIDIA, Ubuntu 22.04 / Zorin 17 / Debian 12.
     Он тоже работает на видеокартах NVIDIA через проприетарный драйвер, а если видеокарты нет,
     работает на CPU.
4. Скачивает с HuggingFace вспомогательные модели программы (с проверкой sha256) и чат-модель
   по умолчанию: [Qwen3-4B-Instruct-2507 Q4_K_M](https://huggingface.co/unsloth/Qwen3-4B-Instruct-2507-GGUF)
   (2.5 ГБ) в `assets/local_llm/`.
5. Создаёт `llama.conf` с настройками под объём видеопамяти и пункт меню
   `~/.local/share/applications/soul-of-waifu.desktop`.

## Как это работает

`launch.sh` (его же вызывает пункт меню):

1. Если на `127.0.0.1:8095` уже отвечает OpenAI-совместимый сервер, использует его.
2. Иначе запускает `llama/llama-server` с моделью и ждёт, пока модель загрузится; ход
   загрузки показывается в уведомлениях рабочего стола.
3. Запускает программу. Когда вы её закрываете, llama-server останавливается.

Программа уже настроена на этот сервер: способ общения **Local LLM**, внешний сервер
`http://127.0.0.1:8095/v1`. Настройки: *Options → LLM Settings → Advanced → Hardware & Backend →
External server (OpenAI-compatible)*. Идентификатор модели определяется автоматически.

### llama.conf

```bash
LLAMA_PORT=8095     # должен совпадать с Server URL в настройках программы
LLAMA_MODEL=""      # путь к .gguf; пусто = первый *.gguf в assets/local_llm
LLAMA_CTX=16384     # размер контекста
LLAMA_NGL=""        # слои на GPU; пусто = сколько влезет в свободную видеопамять, 0 = только CPU
LLAMA_WAIT=300      # сколько секунд ждать загрузки модели
LLAMA_ARGS=""       # любые дополнительные флаги llama-server
```

**Другая модель:** положите любой `.gguf` в `assets/local_llm/` (или скачайте через Models
Hub в программе — он сохраняет туда же) и укажите его в `LLAMA_MODEL`.

**Свой сервер:** запустите llama.cpp, LM Studio, Ollama или любой другой OpenAI-совместимый
сервер на порту 8095 до старта программы, и `launch.sh` подхватит его. Чтобы использовать
другой порт или хост, поменяйте Server URL в настройках программы и `LLAMA_PORT` в `llama.conf`.

## Советы по железу

- **4-6 ГБ видеопамяти (например, RTX 3050/3060 Laptop):** установщик ставит контекст 8K,
  KV-кэш q8_0 и оставляет 1.5 ГБ видеопамяти свободными для распознавания речи и TTS. Слои,
  которые не влезли, работают из оперативной памяти (`--fit` в llama.cpp): медленнее, но
  работает. Выбирайте лёгкие движки озвучки (Edge TTS, Kokoro, Silero): Qwen3-TTS и XTTS
  сами по себе занимают около 4 ГБ видеопамяти.
- **8 ГБ и больше:** настройки по умолчанию подходят, можно пробовать модели 8-12B в Q4_K_M.
- **Без видеокарты:** ставьте с `--cpu`. Небольшие модели (до 4B) нормально работают на
  современном 4-8-ядерном процессоре.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| Из меню ничего не запускается | Запустите `./launch.sh` в терминале и посмотрите ошибку |
| «llama-server exited while loading the model» | Смотрите `logs/llama-server.log`; обычно не хватает памяти: уменьшите `LLAMA_CTX` или задайте `LLAMA_NGL` поменьше |
| Программа пишет, что LLM-сервер offline | Проверьте, что `curl http://127.0.0.1:8095/v1/models` отвечает и порт совпадает с Server URL в настройках |
| Нет звука / не тот микрофон | В разделе *Audio Devices* выберите `default`, `pipewire` или `pulse` |
| Live2D/VRM или веб-страницы чёрные под Wayland | `QT_QPA_PLATFORM=xcb ./launch.sh` |
| Окна компаньона не перетаскиваются под Wayland | Ограничение Wayland для окон, которые двигает сама программа; помогает `QT_QPA_PLATFORM=xcb` |

Логи программы лежат в `logs/`.

## Чем порт отличается от оригинала

- Режим внешнего OpenAI-совместимого сервера для **Local LLM**: интерфейс настроек и
  автоподключение.
- Исправления для Linux: импорты и таймер простоя, которые были только под Windows, пути
  с обратными слэшами, открытие папок, перетаскивание окон под Wayland, выбор устройств
  PipeWire/PulseAudio (запоминаются по имени), пересэмплирование звука под родную частоту
  устройства вывода, моно-TTS на оба канала JACK/PipeWire-устройств, отрисовка Live2D под
  Wayland (контекст desktop OpenGL) и WebGL для VRM на NVIDIA + Wayland (в `start.sh`
  принудительно выбирается EGL от NVIDIA).
- Исправления TTS: загрузка модели больше не съедает таймаут на каждое предложение,
  Qwen3-TTS загружается целиком на GPU.
- Функции только для Windows не изменены и здесь не работают: управление ПК и встроенный
  обновлятель llama.cpp.
